# Адаптація PARCS-Python

Джерело: завантажений користувачкою архів репозиторію Hummer12007/parcs-python.
Початковий код master, worker, scheduler, API та шаблони інтерфейсу збережено й адаптовано.

| Проблема у вихідному коді | Виправлення |
|---|---|
| Debian stretch, python-pip/python-dev для Python 2 | Docker Python 3.12 на Debian bookworm; встановлення через pip |
| Неявні відносні імпорти | Явні `from .module import ...` |
| ConfigParser та Queue | configparser та queue |
| filter використовується як список | Спискові включення там, де потрібні len/індексація |
| `async` — зарезервоване слово Python 3 | `Pyro4.asyncproxy(proxy)` |
| imp видалено у Python 3.12 | importlib.util у module_loader.py |
| Pyro daemon зберігався у властивості Thread.daemon | Окреме поле rpc_daemon: Thread.daemon залишається boolean |
| Визначення IP тільки за префіксом 192.* | Явна приватна IP через аргумент -ip |
| Наявність cpuinfo['brand'], RAM завжди «4 GB» | Читання CPU та фактичної RAM із ОС |
| Випадковий RPC-порт | Фіксований 9090; змінний PARCS_RPC_PORT для локальних тестів |

Додано JSON-відповідь з job_id при поданні задачі та GET статусу задачі для
автоматизації вимірювань. Список proxy впорядковується за IP/портом. Помилки
ініціалізації worker тепер записуються в лог, а не мовчки приховуються.
Непотрібні netifaces і py-cpuinfo вилучено із залежностей.

Це виявлені проблеми сумісності й зроблені зміни; не кожна з них спочатку
відтворювалася як окрема build-помилка. Локальні тести Python 3.12 і реального
PARCS RPC пройшли. Docker-образ та розгортання Google Cloud ще потрібно
перевірити під час запуску у вашому середовищі.
